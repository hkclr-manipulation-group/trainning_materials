## 接第一天：矩阵把多项计算写在一起

**先会：** 坐标、乘法、加法。第一天用两个数表示位置，现在想把整个坐标方向旋转。分别为x、y写规则容易漏项，所以用一个方阵保存规则。

把点写成一列 `p=[2,1]ᵀ`，这里的ᵀ表示把横着写的数转成一列。矩阵的“行”横着，“列”竖着。每一行与输入列对应相乘再相加，得到一个输出数：

```text
R = [ 0  -1 ]     p = [ 2 ]     Rp = [ 0×2 + (-1)×1 ] = [ -1 ]
    [ 1   0 ]         [ 1 ]          [ 1×2 +   0 ×1  ]   [  2 ]
```

这相当于把点绕原点逆时针旋转90°。矩阵不是专门属于机器人的符号，而是多输入、多输出线性计算的紧凑写法。平移多了固定偏移，不属于仅靠2×2矩阵完成的线性映射；加入齐次坐标后可以统一写成矩阵乘法。

**自检：** 把输入换成(1,0)，输出是多少？连续做两次R，结果是什么？答案：(0,1)，再变为(-1,0)。长度不变，方向继续转动；可以在方格纸上检查。

下一步按[矩阵与FK第2至7节](15_frames_matrices_fk.md)学习行乘列、基向量、齐次坐标、乘法顺序与逆变换，再做[Notebook11](../notebooks/11_frames_matrices_fk.ipynb)。参考[Modern Robotics 3.3.1](https://modernrobotics.northwestern.edu/nu-gm-book-resource/3-3-1-homogeneous-transformation-matrices/)，重点看4×4变换矩阵中旋转和平移的分工；不熟矩阵可先看[MIT 18.06](https://ocw.mit.edu/courses/18-06-linear-algebra-spring-2010/)的矩阵乘法与列空间。

## 接第一天：类保存谁的状态，线程安排谁在等待

**先会：** 变量、函数、条件判断；缺基础先读[操作卡](../beginner/COMPUTER_FIRST_STEPS.md)和[软件手册](07_software.md)。

一个函数可以完成“角度换算”。当程序有两个电机，每个都要记住自己的编号、最后角度与反馈时间时，把相关数据和操作放进一个对象会更清楚。类描述这一类对象有哪些数据、怎样更新；实例是其中一个具体对象。`self`就是正在被操作的那个实例。

```python
class JointState:
    def __init__(self, node):
        self.node = node
        self.angle_rad = None
        self.received_at_s = None

    def update(self, angle_rad, received_at_s):
        self.angle_rad = angle_rad
        self.received_at_s = received_at_s

left = JointState(1)
right = JointState(2)
left.update(0.25, 1.0)
print(left.angle_rad, right.angle_rad)  # 0.25 None
```

`None`表示目前还没有数值；两个实例各自保存状态。这个例子仅演示组织数据，还没做数值校验、设备通信和线程同步。只有三行计算时，直接用函数也足够。

再看线程：界面需要响应点击，接收任务可能等待下一条反馈。如果它们挤在一个阻塞的执行流程里，界面可能卡住。线程允许多个执行流程交替推进，但不自动保证计算更快、状态一致或硬实时。

```text
接收线程：收完整消息 → 校验 → 放入有限长度队列
                                      ↓
计算线程：取消息 → 核对编号/时间 → 更新状态 → 计算
界面线程：读取一致的状态快照 → 显示角度和反馈年龄
```

可以用`queue.Queue`协调生产者与消费者；阻塞操作需要合适的超时。队列已满时是丢弃旧反馈、停止接收还是报错，应由业务定义。反馈状态流与一次性动作命令的丢弃策略不能直接共用。关节角和时间戳要作为同一条记录传递，避免读到“新角度配旧时间”。

**自检：** 最新角度0.25rad在1.00s收到，当前1.12s，允许反馈年龄不超过0.10s，能视为新鲜吗？答案：年龄0.12s，已超时；数值看起来正常也不能当作新反馈。只给消息增加线程不会修复超时。

继续阅读[开发工具链](12_developer_toolchain.md)的环境、调试与版本，再看[系统深入](13_systems_deepening.md)的软件状态与时间。语言细节查[Python类教程](https://docs.python.org/3/tutorial/classes.html)的实例与方法、[Queue文档](https://docs.python.org/3/library/queue.html)的`put/get`与超时。这些文档说明语言机制；设备实时性仍取决于整个系统。

## 接第二天：六轴设计为什么不只是多装四个电机

**先会：** 第二天的力矩与关节，前面的矩阵；旋转基础可回到[坐标与FK](15_frames_matrices_fk.md)。两杆例子只在平面里移动工具点。空间任务还会要求工具朝向，例如杯口朝上、螺丝刀沿孔轴进入。

空间刚体位姿通常有三个位置自由度和三个方向自由度。六个独立关节在合适构型下可能提供六维局部运动能力，但“轴数等于六”并不保证所有目标位姿都能到：轴线布置、长度、限位、奇异性和碰撞都会限制结果。常见的手臂与腕部功能划分是设计思路之一，不是所有机器人都必须采用的固定结构。

设计从任务数字开始：工具和工件多重，最远要到哪里，方向如何变化，允许多大误差，多快完成，线缆怎样通过。然后比较轴线布局、传动比、关节范围、刚度和驱动能力，再用FK/IK、碰撞与动力学模型核对。单看CAD外观无法回答这些问题。

### 从一个惯量数到3×3惯量矩阵

力矩用来改变转动状态。绕固定主轴转动的理想模型可写作`τ=Iα`：α是角加速度，I是绕该轴的转动惯量，单位kg·m²。相同质量放得离轴更远，一般更难加速。空间转动要同时描述三个方向及其耦合，因此需要惯量矩阵。

设均匀长方体质量2kg，沿x/y/z边长分别0.4/0.2/0.1m，坐标原点在质心，坐标轴沿边。其对角项为：

```text
Ixx = m(b²+c²)/12 = 0.008333 kg·m²
Iyy = m(a²+c²)/12 = 0.028333 kg·m²
Izz = m(a²+b²)/12 = 0.033333 kg·m²
I = diag(Ixx, Iyy, Izz)
```

`diag`表示将三个数放在对角线上，其余为0。这里由于形状和坐标轴的对称性，非对角项为0；换方向或不对称的质量分布通常会产生非对角项。惯量矩阵同时依赖质量分布、参考点和坐标方向，不能把CAD导出的六个数字随意复制到另一个坐标系。

把参考点移到距质心0.3m、方向沿x的位置，平行轴定理给Iyy和Izz各增加`m×0.3²=0.18kg·m²`，Ixx不变。URDF的`inertial origin`用于给出质心所在的惯性参考系；惯量分量应与该参考系约定一致，不能混用绕关节轴的惯量和绕质心的惯量。

**自检：** 原长方体绕质心z轴，以2rad/s²角加速度加速，忽略其他力矩需要多少？答案约0.06667N·m。若在垂直平面运动，还可能有重力力矩；多关节系统还涉及耦合。这个结果不能单独决定电机选型。

继续看[本体手册](01_body.md)与[工程细节](09_engineering_details.md)的传动、力矩和URDF，再看[Modern Robotics 8.2](https://modernrobotics.northwestern.edu/nu-gm-book-resource/8-2-dynamics-of-a-single-rigid-body-part-1-of-2/)的刚体惯量定义。完整六轴设计还需结构强度、刚度、轴承寿命、热、布线与制造验证；这些是后续工程课题，本节不冒充整机设计验收。

## 接第三天：一条消息下面还有电线和时间

**先会：** 位、字节、序号、超时；先把电压理解为两点之间的电势差，测量和信号判定必须有参考。第三天已经能解释消息的意思，现在追问：接收端从哪里知道0和1，又怎么知道一位结束了？

```text
控制含义：关节1的目标角度0.25rad
字段约定：节点号、序号、整数角度、大小端
帧与链路：边界、校验、仲裁或地址
位的时序：接收端在什么时刻采样
电气与布线：电压、差分、参考地、终端、连接器
```

每层回答不同问题。UART的波特率相同，仍可能因电平不兼容而无法通信；CAN总线上看到波形，也不证明应用的节点号或单位正确。连接器形状不能独自说明协议或针脚定义。

以UART 115200、8N1为例：一帧1个起始位、8个数据位、1个停止位，共10位。传8个字节至少需要`8×10/115200≈0.694ms`，尚未计算帧间空隙、排队和软件延迟。115200不是每秒115200个有效字节。

CAN与RS485常用差分信号：接收器主要看两根线的差，仍受共模范围等器件条件限制；差分不表示可以忽略参考地、屏蔽和收发器要求。以具有两个120Ω端接的典型CAN总线为例，理想并联值是60Ω；额外再并一个120Ω变成40Ω。测量条件和其他电路会影响实测值，不能只凭这一数字判断整条总线正常。

**自检：** CAN帧收到了，但软件报告节点不认识，先读哪层？答案：先对照CAN ID、帧格式、节点映射和应用字段；收帧只排除了一部分底层故障。UART乱码则先核对引脚、电平、波特率、数据位/校验/停止位，再核对上层编码。

本专题的完整本地阅读顺序是[物理连接第1至5节](14_physical_connections.md)的层次、UART、SPI、I²C，再读其中RS485、CAN、USB、Ethernet/EtherCAT；接着看[协议栈与历史](10_communication_stack_history.md)，最后做[物理链路实验](../notebooks/12_physical_links.ipynb)和[协议栈实验](../notebooks/08_protocol_stack.ipynb)。两个实验都可以离线算，无需接设备。

器件资料的读法：在第14章列出的官方来源中，先找本项目收发器的电源与逻辑电平，再看引脚、时序与布线要求，最后回到项目消息定义。完整电气设计还涉及阻抗、反射、EMC、隔离、线缆长度和速率预算，应针对具体器件继续学习。

## 接第四天：为什么逆变换不只是把平移改成负号

**先会：** 第一天扩展矩阵、第15章坐标约定、函数和斜率。约定列向量，`p_A=R p_B+t`，R把B系分量转到A系，t是B原点在A系中的位置。要反过来求p_B，先减去t，再把方向转回去：

```text
p_A - t = R p_B
p_B = Rᵀ(p_A - t) = Rᵀ p_A - Rᵀ t
```

旋转矩阵满足`RᵀR=I`，所以转置是它的逆；一般方阵不能直接用转置当逆。例：R是平面逆时针90°旋转，t=(0.3,0.1)m，则`Rᵀt=(0.1,-0.3)m`，逆变换平移为(-0.1,0.3)m。把p_B=(0.2,0.1)m正向变为p_A=(0.2,0.3)m，再按逆式计算，恰好回到原来的B系坐标。

### 一般矩阵的逆，怎样从解方程得到

对一般方阵A，求逆的意思是找到B，使AB=BA=I，I表示保持输入不变的单位矩阵。例如A的两行是(2,1)、(1,1)，方程Ap=r就是`2p1+p2=r1`与`p1+p2=r2`。两式相减得`p1=r1−r2`，代回得到`p2=−r1+2r2`，所以A的逆两行是(1,−1)、(−1,2)。这种消去未知量的思路会发展成高斯消元。

若A的两行是(1,2)、(2,4)，第二行只是第一行的两倍，提供不了独立信息；此时A没有逆，方程可能无解或有多个解，取决于r。对`[[a,b],[c,d]]`，可逆条件是`ad−bc≠0`，其逆为`[[d,−b],[−c,a]]/(ad−bc)`。这里a、b、c、d是矩阵的四个元素。

**自检：** 用第一组A乘(0.2,0.1)得到什么，再用逆矩阵能否返回？答案(0.5,0.3)，逆变换返回(0.2,0.1)。维度更大时学习线性方程求解、数值精度与条件数；不要在代码中对所有矩阵直接套2×2公式。IK的“逆”也不是把整个非线性FK函数当作一个矩阵求逆，多解、无解和约束都还存在。

### 从“误差小一点”到优化式

FK写成`f(q)`，目标位置为x*，误差`e=x*−f(q)`。在当前q附近，关节小变化Δq引起的末端变化约为`JΔq`；J就是Jacobian。这是局部近似，步子太大时要重新计算。

希望预测误差小，同时不要一步改变太多，便可以最小化：

```text
L(Δq) = 1/2 ‖JΔq − e‖² + λ²/2 ‖Δq‖²
```

`‖v‖²`是把v的各分量平方后相加；第一项惩罚预测误差，第二项惩罚过大步长，λ是阻尼参数。各项需采用一致单位或明确归一化/权重。对Δq求导并令导数为0，得到：

```text
Jᵀ(JΔq − e) + λ²Δq = 0
(JᵀJ + λ²I)Δq = Jᵀe
```

实现中通常求解这个线性方程，不必显式计算矩阵逆。这里J和e在一次更新内固定，下次要在新的q重新计算。导数还不熟时，先用[数学台阶](../beginner/MATH_STEPS.md)理解“输入变一点，输出变多少”，再回来看公式。

**标量手算：** 假设局部关系J=2m/rad，误差e=0.1m，λ=0.5m/rad。则`Δq=2×0.1/(4+0.25)≈0.04706rad`，预测移动0.09412m。阻尼使这一步比无阻尼的0.05rad小；这是一次局部更新，不是已经完成整个IK。

**自检：** J=0且λ>0时，这个方法给多大更新？答案0。增加迭代次数不一定脱离这个停滞点；需检查初值、目标方向与奇异性。数值失败也不能直接证明无几何解。

后续按[IK方法家族](11_inverse_kinematics_families.md)读解集、解析法、Jacobian、阻尼和约束，再做[Notebook09](../notebooks/09_ik_families.ipynb)。真正带关节限位和碰撞的IK，还需约束、步长/信赖域与最终验证；学习[Modern Robotics第6章](https://modernrobotics.northwestern.edu/chapters/chapter6/)时重点辨认数值算法的输入、误差和停止条件。

## 接第五天：高维规划的“保证”究竟保证什么

**先会：** 集合、乘法、概率，正文中的节点与边。两关节可以用(q1,q2)画成平面；六关节的一组角度是六维构型空间里的一个点。维度由状态变量的数量决定，不能因为机器人在三维房间里就把关节空间当三维。

每个关节只取100个值：两关节有10,000种组合，六关节有`100⁶=10¹²`种。假设一秒完整检查一百万种，仅枚举六关节组合也要一百万秒，约11.6天，尚未计入边检查和存储。这个假设速度是算例，不是实测性能。

采样规划用有限样本探索，不要求先铺满全部网格。样本中的两个姿态各自无碰撞，连接它们的运动仍需检查。狭窄通道占空间比例很小时，随机探索可能长时间错过。

### 一个小概率算例，接到证明的条件

假设每次独立均匀采样命中某个关键区域的概率p=0.01，那么n次都没命中的概率为`(1−p)ⁿ`。100次约36.6%，1000次约0.00432%。它解释为什么多次采样可能降低漏掉一个区域的风险，但它**不是完整RRT成功率公式**：找到整条路径还需要多个区域、可连接性、搜索策略和有效的边检查。

在相应算法和问题假设下，概率完备性讨论的是：存在满足条件的可行路径时，采样数趋于无穷，找到路径的概率趋于1。它不承诺某次运行会在指定秒数内成功，也不意味着失败时已经证明无解。精确定义见[LaValle：完备性的几种含义](https://lavalle.pl/planning/node182.html)。

渐近最优性是另一个问题：在相应假设下，样本增加时最佳路径代价趋近最优值。RRT*的理论分析与普通RRT不同；碰撞检查、连接规则、采样和代价条件都属于结论的前提，不能只把算法名称写进报告就视为满足保证。参阅[Karaman与Frazzoli原论文](https://arxiv.org/abs/1105.1186)。

**自检：** “运行10秒没找到，所以目标不可达”哪里错？答案：有限预算内没找到与证明不存在不是一回事；还可能有模型、限位、碰撞近似、初值或采样覆盖问题。记录各阶段拒绝计数，才能继续定位。

接着读[规划手册](04_planning.md)与[系统深入的规划部分](13_systems_deepening.md)。读[LaValle书第4至5章](https://lavalle.pl/planning/)时，先写出构型空间、自由空间、局部连接器和路径存在假设，再看证明思路；本课的二维A*动画不等于高维RRT的实现或证明。

## 接第六天：训练到底改了哪个数

**先会：** 函数、误差平方、导数的斜率意义。第六天的拟合已经是学习的一个例子。神经网络把许多参数化计算串起来，训练仍要明确输入、预测、损失、梯度与更新。

先用只有一个参数的模型`ŷ=wx`。输入x=2，真实值y=3，初始w=1。定义损失`L=1/2(ŷ−y)²`：

```text
前向：w=1 → ŷ=1×2=2 → L=1/2×(2−3)²=0.5
反向：dL/dŷ=ŷ−y=−1；dŷ/dw=x=2
      dL/dw=(−1)×2=−2
更新：学习率η=0.1；w_new=w−η×dL/dw=1.2
再算：ŷ_new=2.4；L_new=0.18
```

反向传播沿计算依赖把导数相乘，再在有多条依赖的地方相加；它计算梯度。优化器使用梯度更新参数，两者承担不同工作。学习率控制每次更新幅度，过大可能越过低损失区域。这里是原创建模算例；计算图与反向传播的系统说明见[D2L相应章节](https://classic.d2l.ai/chapter_multilayer-perceptrons/backprop.html)。

### 再多一层，才看得见“链”

令`h=ReLU(w1×x)`，`ŷ=w2×h`，ReLU把负输入变成0，正输入保持原值。取x=2、w1=0.5、w2=2、y=3，得到h=1、ŷ=2、L=0.5。当前ReLU输入为正，其局部导数为1，所以：

```text
dL/dw2 = (ŷ−y)×h = −1
dL/dw1 = (ŷ−y)×w2×1×x = −4
```

两项梯度都在旧参数上算好。用η=0.1一起更新得w1=0.9、w2=2.1；新预测3.78，新损失0.3042。损失下降但预测越过了3，提醒我们梯度更新不保证一步正好到答案。本例不处理ReLU在0点的导数约定，也不代表一次样本训练能泛化。

### 真正训练还要组织数据与评价

一批样本称为batch；遍历一次训练数据称为epoch。训练集用来计算参数更新，验证集用来选模型或学习率，测试集用于方案确定后的独立评价。连续视频相邻帧非常相似，随机按帧拆分可能把同一场景泄漏到测试集，应按任务、轨迹、对象或采集批次设计拆分。

```text
定义任务与拆分 → 训练批次 → 前向 → 损失 → 反向 → 参数更新
                     ↑                              ↓
                     └──────── 下一批次 ───────────┘
验证集选方案 → 固定方案 → 测试集评价 → 闭环任务评价
```

SGD用当前批次的梯度更新，动量利用更新历史，Adam维护梯度的一阶与二阶统计量。要比较方法，需固定数据拆分、记录种子与超参数，并检查相同任务指标；算法名字本身不决定哪个最好。

**自检：** 第一例把学习率改成1会怎样？答案：w变成3，预测6，损失4.5，比原来更差。第二问：训练误差很低是否代表可抓取？答案：还要检查未见数据、坐标/时间、动作约束和闭环结果。

## 接第七天：小工具怎样长成可核对的系统

**先会：** 单位与参考系、消息与超时、FK/IK、碰撞、测试与版本。第七天交付的是角度到位置小工具。接整机时，要让多个模块对同一件事有一致理解：同一个关节编号，同一套模型，同一种时间和单位。

| 模块边界 | 应写清楚的输入输出 | 一个必须覆盖的失败例子 |
|---|---|---|
| 模型→运动学 | 模型版本、关节顺序、轴与零位、工具坐标系 | 调换两个关节，FK不再符合手算 |
| 感知→目标 | 坐标系、米/像素、时间戳、标定版本 | 把相机坐标直接当基座坐标 |
| 规划→控制 | 路径与时间、关节范围、速度/加速度限制 | 终点合法但途中碰撞 |
| 控制→驱动 | 命令单位、模式、序号、更新频率 | 旧命令重放、反馈超时 |
| 系统→操作者 | 状态、故障原因、日志和恢复条件 | 只有“成功”文字却没有新反馈 |

先规定一个离线状态机：`DISCONNECTED→READY→EXECUTING→DONE`，发生异常转到`FAULT`。状态名是本课示例，需要给每次转移写条件；例如READY要求模型与配置有效且反馈新鲜，DONE要求有符合任务标准的完成证据。故障后的动作和恢复方式由实际设备及任务明确规定，不能只让UI把颜色变绿。

### 把部署拆成可检查的阶段

先在纯函数测试里核对FK、单位和边界，再用假驱动注入延迟、丢失、错误序号和断开。接着把模块串起来，核对日志中目标、预测、反馈和时间；有仿真环境时检查模型和运动接口。到真机阶段，才按团队设备流程核对模式、限位、急停、使能与受控的小范围动作，并记录实测差异。仿真或假驱动通过不能替代真机验收。

完整系统还需打包环境、配置版本、模型版本、启动顺序、日志留存、监控、故障恢复和回退方案。部署记录应让同事知道“哪份代码+哪个环境+哪个模型+哪套参数”产生了结果，读[开发工具链](12_developer_toolchain.md)时以这个问题串起Git、环境管理、CI与数据版本。

**离线练习：** 假驱动每20ms反馈一次，规定年龄超过100ms进入FAULT。在1.00s收到最后反馈，下一次检查是1.12s，填状态与原因。答案：FAULT，反馈年龄120ms超出阈值；这些周期与阈值都是练习设定，不是团队设备参数。恢复时不能只因一条任意消息到来就继续旧动作，要验证设备状态、新鲜反馈和任务恢复条件。
