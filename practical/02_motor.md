# 操作卡2：先读反馈，再让电机动一点

[接线卡](01_wiring.md) → 本卡 → [控制与调参](03_control.md)

开始条件：上一张卡通过，型号、固件、协议和工位停止方法已确认。先选厂家支持该型号的调试工具完成只读和最小运动，再接团队程序；工具、驱动安装包和版本写进交付表。

## 1. 从界面上的词开始

**节点号**用来区分设备；**CAN ID**标识一类总线消息，节点号到ID的映射由电机协议规定。**反馈**是设备返回的测量或状态；**编码器**把轴的位置变成数字。**零位**是角度从哪里起算；**减速比**在本卡定义为电机轴转速除以输出轴转速。**模式**规定输入数字的含义：位置模式收目标角，速度模式收目标转速，力矩/电流模式收对应的输出要求。

同样输入“1”，可能是1度、1弧度、1转/分钟，甚至一个原始整数单位。每次操作前在记录中写出模式、单位、轴侧，不能只写“速度=1”。

## 2. 先把只读通道调通

1. 从型号对应的协议找一个确认为只读的状态或位置请求。记录请求ID、返回ID、标准/扩展帧、数据长度、命令字、字段偏移、符号和单位；不要使用第3天自创的教学帧。
2. 在调试工具中选择实际适配器及通道，填入设备规定的速率与帧格式，先在未使能状态发送一次请求。
3. 保存发送和接收的时间、ID、长度、原始字节，以及解析后的位置、速度、故障状态。工具没有显示的字段标记“未提供”，不填零。
4. 按设备允许的查询周期连续读状态。检查返回是否来自目标设备、是否对应本次请求，以及时间间隔是否符合约定；单纯刷新界面不代表有新数据。
5. 对照实物轴侧和工具读数确认位置范围。只有手册允许、无重力负载且抱闸已按流程处理时才手动缓慢转轴；不可强拧锁止轴。否则用后续经限制的点动核对。

**教学换算：** 假定编码器在电机轴，每圈16384计数，减速比10，读数从1000增加到1164，且没有跨圈，则输出轴变化为 `(1164-1000)/16384×360/10≈0.3604°`。若接口已经返回输出轴度数，就不能再除10。这个算例不是任何实物的默认参数；跨单圈边界还需要根据协议处理回绕，多圈角与单圈角不能混用。

## 3. 对照团队代码，知道数字经过哪里

在当前工作区可用PowerShell只读查找接口：

```powershell
Set-Location D:\code_agent
rg -n 'rmd_motor_init|rmd_motor_decoding|rmd_motor_set_velocity|rmd_motor_get_position' rmd_motor
rg -n 'VCI_Transmit|VCI_Receive|DataLen|ExternFlag' cxt_can_rmd_motor
```

安装路径不同就替换第一行。训练资料单独克隆时还需要对应源码仓库。阅读定位如下：

| 工作区文件 | 看什么 | 能确认什么 |
|---|---|---|
| `rmd_motor/rmd_motor.h` | `MOTOR_TYPE`、`rmd_motor_init`与结构体 | 接口需要类型、ID、减速比、分辨率；结构体保存原始和解析后的状态 |
| `rmd_motor/rmd_motor.c` | 对应型号的编码和解码分支 | 参数怎样变成字节，反馈怎样变成角度或速度 |
| `cxt_can_rmd_motor/cxt_can_rmd_motor.c` | `VCI_Transmit`、`VCI_Receive`及返回检查 | 总线发送、接收和字段解码发生在哪里 |
| `cxt_can_rmd_motor/windows_main.c` | include、初始化、循环和退出 | 旧示例仍使用`serial_can_*`命名，并直接发送正弦速度目标 |

这些文件存在版本差异，不能把不同仓库的声明和旧示例拼在一起就当成可运行工位。旧Windows示例含`90 * sin(...)`目标，且缺少本路线要求的完整状态门禁；先做接口与依赖适配、只读运行及停止处理，再验证运动。协议资料必须与实际型号/固件对应。

## 4. 第一次运动按这个顺序

先填好允许位置区间、速度/加速度/电流或力矩限值、反馈超时、试验持续时间和停止方式，数值来自型号手册与工位负载评估。空白项不进入运动；不同电机没有通用的安全试转速度。

1. 备份原配置，确认机械固定、活动范围和停止通路。读取当前有效位置`q0`及故障状态。
2. 按手册设定模式与限值，读回确认。位置模式先将目标与当前`q0`对齐，速度模式先设零目标，再按设备要求使能；有些设备要求不同写入顺序，以型号流程为准。
3. 发出工位已选定的小幅度、有限时目标：有位置/速度限制的位置运动优先使用工具的受控点动或轨迹功能。记录目标、实际位置、速度、电流和状态。
4. 核对运动方向、轴侧和幅度。出现方向不符、反馈过期、越界趋势、异常声音或故障时执行已定义停止流程，定位后再继续。
5. 停止并确认反馈速度及设备状态符合停止条件，再做反向小幅运动；不要未停稳就反向追赶目标。
6. 正反向和正常停止通过后，在独立固定的工位上验证应用停止发送目标时的超时处理；事先配置并核对设备侧看门狗及停止行为。主机断连后通常发不出停机命令，不能只依靠异常退出代码。
7. 按设备流程退出使能和下电，确认抱闸/支撑已接管需要保持的负载，保存完整记录。

**看门狗watchdog**是“规定时间收不到有效更新就触发预设动作”的机制；要记录它在电脑端还是驱动器端。**失能disable**意味着不再允许某种驱动输出，不保证轴保持静止；速度零目标也不等于断开动力。

## 5. 不动或乱动时按现象找下一步

| 现象 | 先看证据 | 下一步 |
|---|---|---|
| 电脑找不到适配器 | 设备枚举、驱动和通道 | 检查USB、驱动版本、占用进程 |
| 有发送记录、无接收 | 供电、CAN错误计数、速率、终端和请求格式 | 回接线卡逐层核对；不靠反复使能排错 |
| 有帧但读数不合理 | 返回ID、命令、长度、符号与缩放 | 对照原始字节手算一个值，再查型号分支 |
| 有状态但不动 | 故障码、使能、模式、抱闸和目标是否被接受 | 按状态机处理；不盲目加大电流 |
| 幅度相差固定倍数 | 度/弧度、转速单位、轴侧和减速比 | 在接口边界明确只换算一次 |
| 一使能就跳动 | 旧目标、当前角、零位和模式切换顺序 | 停止后对齐当前位置；不要通过改零位掩盖问题 |

过关：交出只读日志、正反向小运动、正常停止、超时停止的实际证据。能解释“发送成功、收到有效反馈、到位”是三个不同判断，再进入控制卡。
