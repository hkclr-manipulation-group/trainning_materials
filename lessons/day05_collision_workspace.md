# 第五天：碰撞近似、工作空间与排错

目标：面对 `no reachable` 能拆分原因，面对球重叠能说明它与真实几何碰撞的关系。

## 1. 为什么用碰撞球

三角网格精细但检查成本可能高。球只需中心和半径，两球表面间隙为 `gap=distance(c1,c2)-r1-r2`。负值表示球体重叠，零是接触，正值是分离。碰撞球应先在各 link 局部坐标系定义，再用 FK 转换到同一坐标系比较。

球模型存在取舍：外扩太多会把实际分离的零件判为碰撞；覆盖不足会漏掉真实接触。球数量、半径上限、覆盖率与外扩误差是不同指标，半径变小不自动保证贴合。

执行 `python labs/course_lab.py collision`。教学例中，两个物体用一维区间代表，其间有 4 mm 间隙；过大的包络球却重叠 10 mm。这个反例说明误判机制，不构成三维 mesh 验证方法。

## 2. 我们遇到的折叠误判

D2026 设计与 `spark2_v2` 的几何、零位、末端框架和限位并不完全相同。最近的项目问题包括腕部球包络外扩，使折叠姿态过早被拒绝。应保存关节角、碰撞 link 对、球索引、球间隙和模型版本，再对照实际网格。新的紧贴拟合方案仍需覆盖与外扩验证；本课不把开发中的方案当作已验证结果。

在安装 viewer 依赖的碰撞项目中运行：

```powershell
python -m collision_shpere_generation.viewer --model D20260901B
```

逐轴拖动，切换 mesh/球显示，选中碰撞对并隔离观察。临时排除只用于诊断；不能因为排除后结果变好，就把非相邻连杆永久忽略。导出 JSON 复现记录，换电脑也能分析。

## 3. 可达与灵巧工作空间

对每个位置采样 K 个姿态，若至少一个姿态成功，则该点在本次采样下可达。成功比例 `d=成功姿态数/K` 表示采样姿态覆盖率；`d=1` 表示所有采样姿态成功，并不证明连续的全部姿态均可达。经典灵巧工作空间与有限采样估计应区分。

本项目还按 `minimum_dexterity` 过滤显示。如果设为 1，12/16 个姿态成功的位置会被过滤，尽管它可达。网格体积约为有效格点数乘 `dx*dy*dz`，结果受边界、步长、姿态采样、IK seed、误差容限和碰撞策略影响。

## 4. 按证据排错

| 症状 | 先检查 | 可支持的结论 |
|---|---|---|
| lower velocity limits… | URDF 是否 velocity=0 | 零值可能导致上下界均为 0 |
| loader 中 str/value 异常 | 完整 traceback、关节轴和解析器 | 接口/模型兼容性问题，不等于 IK 无解 |
| 所有随机姿态都碰撞 | 碰撞对频率、局部框架、球拟合 | 当前采样下被球模型全部拒绝 |
| IK 返回成功但图空 | 过滤阈值、输出文件、绘图范围 | 可能是筛选或显示问题 |
| 两设计结果差很大 | 几何和相同计算设置 | 先建立公平对照，再解释差异 |

在 dexterous 项目中先运行 `python run.py --config configs/D20260901B.yaml --validate-only`，再运行同命令的 `--diagnose-only`。CPU 碰撞诊断不是 GPU IK；关闭碰撞只可用作诊断对照，输出必须标注。
