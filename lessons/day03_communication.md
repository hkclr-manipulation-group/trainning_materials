# 第三天：从字节到电机反馈

目标：能够逐字节读一帧教学报文，并按层定位超时、错误解析和反馈不更新。

## 1. 分清电气接口、传输和应用协议

| 名称 | 入门理解 | 调试重点 |
|---|---|---|
| UART | 异步串行通信外设 | 波特率、数据位、校验、停止位 |
| RS-485 | 差分电气接口 | 接线、终端、方向控制；上层协议另定 |
| SPI | 时钟同步的近距离总线 | 时钟模式、片选、位序、时序 |
| USB | 主机与设备的通信体系 | 枚举、驱动、接口、端点与传输 |
| CAN / CAN FD | 带仲裁和错误检测的总线 | 速率、ID、负载、错误状态 |
| TCP / UDP | IP 网络上的传输协议 | TCP 字节流分帧；UDP 丢包、乱序、长度 |

经典 CAN 单帧数据最多 8 字节，CAN FD 最多 64 字节；FD 的长度编码不是所有整数长度都直接对应。CAN ID 用于标识和仲裁，不天然等同于电机节点号。发送成功或 CAN ACK 都不代表指定电机已经执行了动作。[Linux 内核 SocketCAN 文档](https://www.kernel.org/doc/html/latest/networking/can.html) 可用于理解帧结构、过滤和错误帧。

本课程只讲常见总线概念，不把一个厂家的命令码套用到另一个型号。速率、接线和终端参数应查当前硬件手册。

## 2. 教学协议：能手算才算读懂

离线实验定义一个自创的 8 字节数据载荷，**不属于 RMD、Spark2 或任何真实电机协议**：

| 字节偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 1 | 固定教学标记 `0xA1` |
| 1 | 1 | 节点号 1–255 |
| 2–3 | 2 | uint16 序号，小端 |
| 4–7 | 4 | int32 角度，单位毫弧度，小端 |

`a1 01 07 00 fa 00 00 00` 表示节点 1、序号 7、角度 0.250 rad。小端表示低有效字节在前；有符号数还必须按补码解释。量化到毫弧度会带来不超过约 0.0005 rad 的舍入误差。

执行 `python labs/course_lab.py protocol`。改变输入角度为负数，检查解码是否恢复数值；删掉一个字节，必须报错，不能悄悄补零。模拟反馈年龄 120 ms、超时阈值 100 ms，应判为过期。

## 3. 真正的链路比一根 CAN 线长

我们 `usb2can/docs/hardware_topology.md` 描述的链路是主机 → H750 → 两条 SPI → 两块 F446 → 各自 CAN 通道。逻辑通道不等于电机 ID。排查时分别记录主机发送、桥接接收、CAN 发送、反馈接收、应用解析的计数和时间。

日志至少包含单调时间、通道、方向、帧 ID、字节数、原始十六进制、解析结果和状态码。关联命令与反馈时需要看序号语义及回绕，不能只判断“有包回来”。

超时后的状态机可以从 `READY` 转到 `FAULT`；重连后重新确认反馈和模式。重试读取通常与重试运动命令不同：上一次运动命令可能已经执行，盲目重发可能重复动作。

## 4. 工具练习与交付

用十六进制输出核对载荷；有网络抓包演示时使用 Wireshark 的显示过滤器区分观察对象。抓包看见报文只能证明该观察点收到了它。SPI 时序则适合逻辑分析仪，电压和边沿问题适合示波器。

交付：字段表、正常与错误帧、一次超时判断，以及五层链路的排查顺序。工具步骤见 [TOOLS.md](../TOOLS.md)。下一课：[运动学与控制](day04_control.md)。
