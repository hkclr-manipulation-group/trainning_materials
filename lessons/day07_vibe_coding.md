前六天走过了本体、消息、运动、避障与学习。今天不增加大量新算法，而是把“输入→计算→检查→输出”做完整。

## 第1步：把需求写成看得见的结果

“做一个机器人软件”太大。先缩小为：输入两根杆的角度，输出末端位置；错误输入要解释原因。这个目标能手算、能测试，也能让别人复现。

输入不是只写“两个数”，还要写“两个角度，单位度”；输出写“横向和竖向位置，单位米”。定义越清楚，越容易发现错误。

## 第2步：读懂最小实现

```python
import math

def endpoint_cm(q1_deg, q2_deg):
    q1 = math.radians(q1_deg)
    q2 = math.radians(q2_deg)
    x = 30 * math.cos(q1) + 20 * math.cos(q1 + q2)
    y = 30 * math.sin(q1) + 20 * math.sin(q1 + q2)
    return x, y

print(endpoint_cm(0, 90))
```

def表示定义一组可重复使用的步骤，称为函数；括号中的名字是输入；return把结果交回去。函数名endpoint_cm提醒结果是厘米。预期约(30,20)，极小浮点误差可以接受。

若主工具输出要求米，要再除100，或全程把杆长改成.3和.2米。不要只修改变量名却忘记换数值。

## 第3步：测试像提前写好答案的检查题

先用自己已经会算的姿态：(0°,0°)应为(50,0)厘米；(0°,90°)应为(30,20)；(90°,0°)应为(0,50)。再考虑错误：缺角度、文字不是数字、无限大或NaN。

NaN表示“不是一个有效数值结果”。遇到它应明确失败，不能把它当0继续。测试的目的不是让屏幕总显示绿色，而是检查约定是否实现。

运行`python -m unittest discover -s tests -v`。输出中每项测试说明一个检查；失败时先看测试期望和实际结果，不直接删掉失败的测试。

## 第4步：AI怎样帮助写代码

vibe coding可以理解为：用自然语言描述需求，让AI协助生成和修改代码。AI能快速给出草稿、解释和测试，但它也可能猜错接口、单位或运行结果。

一个好请求可以这样写：

```text
请读取 labs/course_lab.py 中的 fk。
我要新增一个命令行入口，输入两个角度（度），输出位置（米）。
使用30厘米和20厘米的教学两连杆，不连接设备。
角度必须是有限数字，错误输入返回清楚原因。
请用三个手算姿态和一个错误输入验证，并告诉我实际运行结果。
```

先读AI改了哪里，逐项核对输入单位、输出单位和错误处理，再运行。让AI自己写代码又自己说“正确”，还不构成独立证据；你的手算例子就是额外的一份证据。

## 第5步：保存改动与复现步骤

Git可以保存文件的版本变化。status告诉你哪些文件变了；diff显示具体差异；提交把一组变化记录成一个版本。按 [工具操作卡](../beginner/COMPUTER_FIRST_STEPS.md) 做一次小改动，不需要今天学会所有Git命令。

README就像工具的说明书，至少写“需要什么、在哪运行、输入什么、输出什么、失败怎么办”。把工具复制到另一目录，自己重新按说明运行。成功后才知道没有偷偷依赖原来目录里的文件。
