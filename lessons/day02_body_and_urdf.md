# 第二天：从机械本体到机器人模型

深入自学：[本体与CAD步骤](../handbook/01_body.md)、[运动学1–3节](../handbook/02_kinematics.md)。没有CAD软件先做纸笔尺寸与坐标图。

![连杆角度与不同构型](../assets/figures/two_link.png)

目标：从任务需求推导本体的关键约束，再把几何与关节关系转换成软件能使用的模型。

## 1. 先写需求，再画零件

假设任务是在桌面上搬动 0.5 kg 物体，最远水平距离 0.4 m。先明确可达范围、工具和载荷总质量、重复定位要求、节拍、安装姿态、线缆走向和维护空间。负载不仅是物体，也包括夹爪、转接板和线缆作用。

静态估算 `τ = m g l`：只计算这件物体，对某水平支承关节贡献约 `0.5×9.81×0.4 = 1.962 N·m`。实际关节还承受连杆和工具的重力矩、加速惯性、摩擦；额定连续力矩与短时峰值也不同。这个数只是教学下界，不能直接拿来选电机。

减速比提高输出力矩并降低输出转速，但效率、背隙、扭转刚度和反驱性会影响控制。轴承承担载荷，减速器和电机不能代替所有支承设计。折叠时除了零件干涉，还要看线缆弯曲、接头和装配公差。

## 2. CAD 的最小实践

用团队已有 CAD；没有授权软件时可用 FreeCAD。建立两个长度为 300 mm、200 mm 的连杆草图，添加尺寸约束、拉伸，建立转轴和装配关系。提交尺寸图、装配零位和两个折叠姿态。FreeCAD 的官方 [入门手册](https://www.freecad.org/manual/a-freecad-manual.pdf) 可用于熟悉参数化建模；界面位置按安装版本核对。

STEP 通常适合交换实体几何，STL 是三角网格且通常不携带明确单位或关节语义。原生 CAD 保留设计历史。导出 STL 后量一次包围盒：300 mm 的杆在以米为单位的模型里应约 0.3 m，不能只看屏幕上“大小正常”。

## 3. URDF 中每一项回答什么问题

| 字段 | 意义 | 检查方法 |
|---|---|---|
| link | 刚体或附加坐标框架 | 名称是否唯一，基座和工具是否明确 |
| joint parent/child | 树中两个 link 的连接 | 能否从基座走到末端 |
| origin xyz/rpy | 零位时的关节坐标变换 | 与 CAD 的装配零位比较 |
| axis | 关节坐标系下的运动轴 | 按右手规则转动，核对方向 |
| limit | 位置、速度、力或力矩约束 | 单位、正负、大小关系是否正确 |
| visual / collision | 显示模型 / 碰撞近似 | 两者可不同，均有自己的局部变换 |
| inertial | 质量、质心和惯量 | 物理上是否合理，是否与几何单位一致 |

```xml
<joint name="joint1" type="revolute">
  <parent link="base"/>
  <child link="link1"/>
  <origin xyz="0 0 0.1" rpy="0 0 0"/>
  <axis xyz="0 0 1"/>
  <limit lower="-1.57" upper="1.57" velocity="1.0" effort="2.0"/>
</joint>
```

这是说明字段的片段，不是完整机器人文件。示例限位不是 Spark2 参数。link 的 mesh 原点不一定是关节原点；把显示网格平移后“看齐”，并不能修正错误的运动学链。

## 4. 我们的模型为什么需要分包

CAD 原件用于设计追溯；碰撞项目需要 URDF 和引用的 mesh；工作空间项目使用运动学 URDF、碰撞球和排除关系即可。分包减少运行依赖，但每次更新必须记录源模型、版本、哈希和导出选项。

按 [项目地图](../PROJECT_MAP.md) 阅读 `spark2_design` 和两个项目的 `models`。任选一个模型，抄出基座、末端、关节名称、轴和限位。比较 `spark2_v2` 与 D2026 设计时，先核对零位、尺寸、工具框架和限位，再谈工作空间大小。

交付：两连杆尺寸图、静态力矩计算、一个模型字段表和一项发现的不确定参数。完成第 2 天测验。下一课：[通信](day03_communication.md)。
