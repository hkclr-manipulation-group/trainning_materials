# 让动画解释原因：九个离线逐步主题

在文件夹中双击 [concept_player.html](concept_player.html)，用浏览器打开。无需联网、安装新包或启动Jupyter。若编辑器只显示源码，请使用文件管理器的“打开方式→浏览器”。

默认暂停；可选择主题、上一步/下一步、拖动进度、调整播放速度。到最后一步自动停下，切换主题回到第一步。代码计算发生在生成阶段；要改参数并重新计算，用[三个专题Notebook](../../DEPTH_MAP.md)，不是编辑HTML里的预计算结果。

## 每个主题应该看出什么

| 主题 | 保持不变 | 要看的变化 | 先问自己 |
|---|---|---|---|
| 协议栈 | 同一份8B应用载荷 | 逐层加头、逐层取出，长度8→16→36→50 | UDP长度16为什么不是载荷16？ |
| CAN逐位仲裁 | 0x120与0x100两个标准数据帧ID | 从高位比到bit5，发1读0的一方退出 | 谁赢，在哪一位确定？ |
| IK两解与平均 | 两杆长度、同一个目标 | 两个有效构型与错误的平均构型 | 平均q为何不保持FK结果？ |
| Jacobian局部近似 | 初始q和同一个J | 真实弯曲轨迹与直线预测逐渐分离 | 哪条线表示近似误差？ |
| IK迭代与停滞 | 同一个目标和算法参数 | 弯曲seed下降，直杆seed停滞 | 局部失败为何不能证明无解？ |
| A*逐步搜索 | 同一地图、代价与起终点 | 当前节点、已扩展集合、g/h/f、最终路径 | 蓝格是已扩展还是候选队列？ |
| 反馈延迟对照 | Kp、dt与目标 | 无延迟/80ms延迟的实际位置和旧反馈 | 机器人已过目标，为什么还在推？ |
| 滤波与滞后 | 真值、扰动、Q | R改变后噪声抑制与阶跃跟随变化 | 平滑为何不等于更及时？ |
| 碰撞近似覆盖 | 两个矩形与真实4mm间隙 | 圆从过大、适当到覆盖不足 | 为什么不能只把碰撞球缩小？ |

每帧下方都有四行说明：**看哪里、观察、解释、边界**。蓝/绿/红同时使用名称、线型和数值区分，不能只靠颜色猜。文字是逐步字幕，不是语音配音。

## 与原有动画的关系

原来的12段GIF与分镜继续用于快速浏览。这一轮重点补强容易误解的内容：

| 原主题 | 原版容易遗漏的理解环节 | 本轮补强 |
|---|---|---|
| 杠杆、坐标、旋转、FK | 单位、相对角、与现实对象的对应 | 在深化手册补充指标和推导；原动画仍作起步 |
| 通信 | 只看到包在移动，不知道每层做什么 | 增加协议栈和逐位仲裁，配字节实验 |
| IK | 只看到手臂靠近目标，没看出多解和失败 | 增加双分支/平均反例、seed停滞与数值残差 |
| A* | 只看到格子亮起，不知道为什么选它 | 显示g/h/f，区分当前与已扩展，保留最终19步 |
| 轨迹、反馈 | 容易把播放速度当真实控制频率 | 画面标物理时间；新增同参数延迟对照 |
| 滤波 | 平滑曲线看起来总更好 | 固定噪声并展示真值突变后的滞后 |
| 学习 | 预设移动线条与实际优化容易混淆 | 第六天播放真实梯度记录；新增IK数据候选＋细化 |
| 碰撞 | 缩小球看起来就“修好了” | 保留覆盖不足警示，补充保守近似和边检查 |

这是一轮针对学习问题的内容改进，不表示原来的每段GIF都重做成新的数值模拟。真实机器人几何、自碰撞、动力学和完整网络控制器没有被这些简化图替代。

## 维护与来源

运行 `python tools/build_concept_player.py` 可重新生成HTML和 [manifest.json](manifest.json)。算法来自课程模块，SVG与字幕为原创；播放器脚本只控制预计算画面的显示，不访问设备或远端服务。页面文本与SVG使用UTF-8。

协议史见[通信专题](../../handbook/10_communication_stack_history.md)，数学假设见[IK专题](../../handbook/11_inverse_kinematics_families.md)和[其他主题深化](../../handbook/13_systems_deepening.md)。
